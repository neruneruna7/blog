### 依存関係
入力 <- ロジックや型定義 <- 出力
という依存関係は，処理の整理において一定の成果を得られた．
一方で，それぞれの処理の再利用性に問題を抱える結果となった．
ロジックや型定義が，入力について知っていなければならないからだ．別の言い方をすれば，前段が変われば後段全てが影響を受けうる．

入力 -> ロジックや型定義 <- 出力
という依存関係が望ましいのではないか．

もっと言えば，
入力 -> 型定義，ふるまい定義 <- 出力
型定義，ふるまい定義 <- 具体的なロジック(複数ありうる)
という依存関係が望ましいのではないか．

あれ，これってなんかDDDやらなんとかアーキテクチャで見たような?

まずは，
入力 -> ロジックや型定義 <- 出力
という依存関係を作る．そこからは再度検討だ．
